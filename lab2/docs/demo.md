# Инструкция для демонстрации лабораторной работы №2

## Задание 2.1 — Inject → Debug

1. В каталоге репозитория выполнить `docker compose -f lab2/docker-compose.yml up -d`, затем открыть [http://localhost:1880](http://localhost:1880).
2. В верхней части редактора открыть вкладку **«2.1 — Inject Debug»**.
3. Справа открыть панель **«Отладочные сообщения»** (значок жука). Поток уже работает по таймеру; для дополнительной ручной проверки можно нажать квадратную кнопку слева на ноде Inject.
4. В Debug должны появляться новые полные объекты `msg` каждые 5 секунд. Проверить `payload: "Sandrakula"` и `topic: "lab2/Sandrakula/basic"`.
5. Краткое объяснение преподавателю: Inject формирует сообщение по таймеру, записывает строку в `msg.payload` и тему в `msg.topic`, затем передаёт объект по соединению; Debug получает его и показывает весь объект `msg`, включая служебный `_msgid`.

Для быстрого подтверждения версий показать [00-nodejs-version.png](../screenshots/00-nodejs-version.png), а для подтверждения работы потока — [01-inject-debug.png](../screenshots/01-inject-debug.png).

## Задание 2.2 — Function

1. Открыть вкладку **«2.2 — Function»** и панель **«Отладочные сообщения»**.
2. Нажать квадратную кнопку слева на Inject **«Число 6»**.
3. В Debug должен появиться объект: `student = Sandrakula`, `input = 6`, массив `squares`, `total = 91` и категория «большой результат».
4. Объяснить ноды: Inject создаёт число, Function выполняет JavaScript-код, Debug показывает результат из `msg.payload`.
5. Объяснение кода простыми словами: число преобразуется в Number; цикл `for` перебирает числа от 1 до входного; каждый квадрат добавляется в массив и общую сумму; `if/else` выбирает категорию; затем объект результата записывается в `msg.payload` и сообщение возвращается через `return msg`.

Скриншот: [02-function.png](../screenshots/02-function.png).

## Задание 2.3 — Switch

1. Открыть вкладку **«2.3 — Switch»** и очистить Debug при необходимости.
2. Нажать Inject **«Число 6 → результат 91»**, затем **«Число 3 → результат 14»**.
3. В Debug должны появиться два сообщения: `91` от ноды **«Ветка 1: ≥ 50»** и `14` от ноды **«Ветка 2: < 50»**.
4. Объяснить ноды: Inject дают два тестовых числа, Function считает сумму квадратов, Switch проверяет `msg.payload`, две Debug-ноды показывают разные выходы.
5. Объяснение кода: вычисление почти такое же, как в 2.2, но числовая сумма записывается прямо в `msg.payload`, чтобы Switch мог сравнить её с `50`; подробности остаются в объекте `msg.calculation`.

Скриншот: [03-switch.png](../screenshots/03-switch.png).

## Задание 2.4 — Change

1. Открыть вкладку **«2.4 — Change»** и панель Debug.
2. Нажать Inject **«Исходное сообщение»**.
3. Развернуть объект в Debug. Должны быть видны текст `Сообщение обработано для Sandrakula`, topic `lab2/Sandrakula/change` и числовой timestamp.
4. Объяснить ноды: Inject запускает поток, Change без JavaScript меняет три поля сообщения, Debug показывает полный объект `msg`.
5. Пояснить, что `$millis()` — встроенное выражение JSONata, которое возвращает текущее время в миллисекундах на момент обработки.

## Задание 2.5 — Template

1. Открыть вкладку **«2.5 — Template»** и очистить панель Debug.
2. Нажать Inject **«Данные студента»**.
3. Развернуть `msg.payload` в Debug. Проверить поля `student = Sandrakula`, `subject = Visual Programming`, `lab = Node-RED` и строку `Student Sandrakula is working with Node-RED`.
4. Объяснить ноды: Inject передаёт исходный объект и topic; Template подставляет его значения в Mustache-шаблон и создаёт JSON; Debug показывает готовый объект.
5. Объяснить выражения `{{payload.student}}`, `{{payload.subject}}` и `{{payload.lab}}`: это ссылки на поля входного объекта сообщения.

## Задание 2.6 — HTTP Request

1. Открыть вкладку **«2.6 — HTTP Request»** и очистить панель Debug.
2. Нажать Inject **«Выполнить GET»**.
3. Развернуть объект в Debug, затем поле `payload`. Проверить `statusCode: 200` и разобранные поля `userId`, `id`, `title`, `completed`.
4. Объяснить ноды: Inject запускает запрос вручную; HTTP Request выполняет GET к JSONPlaceholder и преобразует JSON-ответ в объект; Debug показывает полный `msg`.
5. Подчеркнуть, что `ret = obj` в настройке HTTP Request обеспечивает разбор JSON без дополнительной Function-ноды.
